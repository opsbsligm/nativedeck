# Linux 移植的增量安全审查

此记录针对新增移植代码，不把流水线成功等同全仓无漏洞。旧取证源码快照中的告警保留；最终以本MR最新SHA的扫描报告为准。

## 已修改

- SDK安装器改用显式异常验证固定微软HTTPS下载地址、SHA-512、展开体积和目标目录。Python `-O`下这些检查仍执行；加入优化模式的错误哈希/错误地址回归。已有SDK目标会在下载前拒绝覆盖。
- `linux_host_readable`用带errno/结束位置/地址范围检查的 `strtoumax`解析固定的 `/proc/self/maps`，不再用字符串扫描写入数组。目录同步使用常量`.`或原路径截断后的目录，去掉无界复制调用。
- 映射与临时文件同步使用 `O_NOFOLLOW`，映射后依文件描述符 `fstat`核对普通文件和长度，再对同一描述符 mmap；追加符号链接拒绝用例。
- 可选诊断开关仅判断是否存在，使用glibc `secure_getenv`，不把环境变量字节拼入路径、格式串或命令。

## 保留并说明的通用API发现

文件打开类检测可能继续列出 `open/fopen`。映射路径先打开后在同一描述符核对属性，没有“检查一个路径后重开另一个对象”的流程；`/proc/self/maps`是固定的内核生成文件；缓存临时文件和父目录属于普通deck用户的应用目录，进程内由原有缓存锁串行化。同步后rename用于本地缓存发布，不承担不互信用户之间的授权边界。该代码没有提权能力。对恶意同UID进程、文件被同时截断等场景，不能据此承诺完全防护，原发现不从报告中隐藏。

进程创建类的High候选涉及固定命令参数数组：`ninja -f <本地生成文件> -j <1..4> -k 0`，以及 `git -C <解析后的绝对目录> rev-parse HEAD`。没有 `shell=True`，参数不会直接作为shell代码解释；源码应用器还拒绝错误提交、脏树和覆盖overlay。构建工具按设计编译已核对的公开源码和玩家本地生成代码，不能用于隔离恶意源码。审查结论是这些具体调用没有形成报告所述的shell命令注入，保留原始发现与适用范围，不新增全局忽略规则。

依赖扫描没有适用的包管理清单时，只能说明该扫描器不适用，不能证明所有C/C++系统依赖或构建期NuGet包无漏洞。跨文件扫描沿用项目已有 `allow_failure=true`豁免，须单列本次执行结果。游戏实机、中文、Xbox图标、存档及性能仍未验收。
