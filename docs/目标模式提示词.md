# nativedeck 目标模式提示词（v1 · 待用户核准）

> 用法：核准后作为 `create_goal` 的 objective 正文；`安全基线.md` 为其不可协商的约束附件。
> 关键设计：**ROM 缺失不阻断前三个里程碑**，因为静态重编译的产物本身不含游戏数据。

## 一、objective 正文（会写入 goal）

```
在用户自有 Steam Deck（deck@192.168.x.105，SteamOS 3.9.5，hostname steamdeck）上，
用"原生可执行 + 无兼容层"的标准，逐里程碑推进 Switch AArch64 游戏（终极靶：塞尔达传说 王国之泪）
到 x86-64 Linux 原生移植的可行性验证，直到达成 M1（本机产出并证实原生 x86-64 ELF）
或命中安全基线第 6 节中止条件为止。

验收硬标准（三条同时成立才算"原生"）：
  ① 产物是 ELF 64-bit x86-64，`file`/`readelf -h` 直读为 EM_X86_64；
  ② `ldd` 依赖里不存在 wine/proton/dxvk/box64/qemu/fex 任何一项；
  ③ 运行期 `cat /proc/<pid>/maps` 无 wine/box64/FEX 映射，且进程直接持有 Vulkan 设备。
禁止以"模拟器/Proton 也能跑"作为替代方案或降级结论。

每个里程碑必须：先只读取证 → 单一变量写入 → SHA/日志读回 → 写 deckprobe/envNN.txt → 升级对应标记。
M0/M1/M2 不需要游戏 ROM，必须在无 ROM 条件下穷尽完成，不得以"缺 ROM"为由提前停手。
M3 及之后若缺 ROM，标记 blocked 并交付精确资产清单（含所需游戏版本与 keys 类型），不自行获取 ROM。
hardware_validated 只在看到用户可见结果（真机画面/帧率）后升级，其余一律 false。
全程遵守《安全基线.md》：不写 rootfs、不用 root、不碰 Decky/兼容工具/Steam 前缀、
不重启不关机不改服务、删除仅限本项目白名单目录、不写入任何版权内容与密钥。
```

| ID | 目标 | 需 ROM | 通过判据（可核对） | 失败时的正确动作 |
|---|---|---|---|---|
| **M0** | 打通真机 GUI 显示通道，闭合 V1 | 否 | 在 Deck 屏幕上看到 LAS 启动器窗口（截图为证）；或 ScarletNX `--version` 列出渲染后端 | 若三种投递方式全失败 → 记 `v1_gui_launch=blocked(display)`，转 M1，不硬试第 4 种侵入式方案 |

| **M2** | 无 ROM 功能面探测 | 否 | 枚举 Vulkan device/扩展、输入设备（含 gyro 可见性）、着色器编译链可预热；ScarletNX 无 ROM 时的 UI/设置面 | 记 `input_validated=false` 并写清阻断层 |
| **M3** | V2/V4 真机运行 TOTK | **是** | 真机进游戏画面 + 帧率采样；`hardware_validated=true` | 缺资产 → blocked + 资产清单 |
| **M4** | V5 手柄映射 + 体感 | 是 | ABXY 布局正确、六轴陀螺仪在 Deku Read 生效 → `input_validated`/`motion_validated` | 按 §19/§20 已列根因逐项隔离 |
| **M5** | Gaming Mode 入库 | 是 | 掌机模式可见可启动 | **需用户单独批准**：写 `shortcuts.vdf` 属 Steam 配置写入，与安全基线红线 2 冲突 |

## 三、ROM 缺失下的 M1 路线（本轮调研结论，供你判断是否照此执行）

静态重编译（static recompilation）的产物是**替换 HOS API 后的原生可执行文件，不含游戏数据**，
因此构建与"原生性证明"完全可以在没有 `.xci` 的情况下完成：

1. **LAS Recomp**（MIT，需 clang/LLVM + cmake）：从源码构建 → 产出 linux-x86_64 可执行，运行时才要求用户选游戏目录。
2. **totk-recomp**（MIT，TOTK 1.0.0 专用）：官方指定用 distrobox(Ubuntu 24.04) 构建，`dist/` 可直接拷回运行 —— 与 TOTK 靶最贴合。
3. **ScarletNX**（GPL-3.0，通用）：已有官方 AppImage，可作为 M0/M2 的无 ROM 探针。

推荐顺序：**ScarletNX 探针（M0/M2，零构建）→ distrobox 建立（M1 前置）→ totk-recomp 源码构建（M1）**。

## 四、需要你在核准时一并拍板的两点

1. **M5 是否纳入本次目标**：入库 Gaming Mode 必须写 Steam 的 `shortcuts.vdf`，与"别碰 Steam 相关组件"直接冲突。默认**排除**，只做到桌面/终端启动。
2. **ROM 与 keys 的来源**：M3 需要你自己提供 TOTK 的 `.xci/.nsp` + 对应 `prod.keys`（+ 若为加密 dump 还需 `title.keys`）。我只在你把文件放到 Deck 的 `~/native-recomp/roms/`（该目录由我按白名单新建）之后才推进，且不会把副本回传到 Mac 或 GitLab。
