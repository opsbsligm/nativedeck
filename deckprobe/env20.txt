## 一、方法变更（关键，决定 M0 能否闭合）
10-25 的失败路（x11grab 抓 :0 纯黑、xwd -id 0 字节、无 grim、card0 不可读）根因是
"从显示服务器抓"，而 Deck 的显示由 gamescope 做 DRM/KMS 合成，X 根窗口本身不是像素源。
本轮改为从**渲染进程自己**取帧：ScarletNX 自带 unattended 截图面
（src/nx/runtime/settings.txt 的 `shot` / `shot_every`，实现在
 src/nx/gpu/vk/renderer.c 的 vkr_screenshot→surf_save：把最后一张 present 的 surface
 blit 成 RGBA8 后 vkMapMemory 回读，写 P6 PPM，并给出 FNV-1a 像素哈希）。
→ 这条链不经过 X/gamescope，取到的就是 Vulkan 提交给 swapchain 的真实帧，
  对"原生渲染证据"比抓屏更强（抓屏还可能混入合成器与桌面包）。

## 二、判据③ 纯净复现（已验证）
本次显式设 `VK_LOADER_LAYERS_DISABLE=~implicit~`、清空 `VK_INSTANCE_LAYERS`：
  载荷进程 pgrep -x scarletnx = 43722（外壳 43703）
  fd: 30 -> /dev/dri/renderD128 / 31 -> /dev/dri/renderD128     ← 直持 GPU render 节点
  grep -icE "wine|proton|dxvk|box32|box64|qemu|fex|steamruntime|lsfg|VkLayer" maps = 0
  maps 内所有 vulkan 相关 file-backed 项：
    /usr/lib/libvulkan.so.1.4.350          ← 系统 Vulkan loader（rootfs 只读使用）
    /usr/lib/libvulkan_radeon.so           ← RADV 驱动，真机 GPU
    （另 intel/nouveau/virtio 为 ICD 枚举一并加载，非使用）
  上一轮的 ~/.local/lib/liblsfg-vk-layer.so 与 libVkLayer_MESA_device_select.so 均已消失
  → 观感污染解释成立：那是隐式层，与本项目无关；禁用后不影响运行
  maps 454 行；进程环境仅 DISPLAY=:0 / XDG_RUNTIME_DIR=/run/user/1000 / VK_LOADER_LAYERS_DISABLE
→ 判据③ 在"零隐式层"条件下复现成立（比 env19 更强）。
